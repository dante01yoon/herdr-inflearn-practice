[herdrdev/herdr](https://github.com/herdrdev/herdr) 저장소의 공개 이슈와 정식 릴리스를 확인하는 대시보드입니다. 이슈 목록에서 번호, 제목, 라벨, 작성일, 열림·닫힘 상태를 볼 수 있으며, 제목을 누르면 GitHub 원문이 새 탭에서 열립니다.

표시 범위는 최근 이슈·PR 응답 30개에서 PR을 제외한 이슈입니다. 화면의 전체 개수와 라벨 통계는 **현재 불러온 데이터 기준**이며, 저장소 전체 통계가 아닙니다.

## 설치 및 실행

Node.js 22.12 이상이 필요합니다. 프로젝트 폴더에서 의존성을 설치합니다.

```bash
npm install
```

개발 모드에서는 다음 명령으로 React 화면과 API 서버를 함께 실행합니다.

```bash
npm run dev
```

브라우저에서 <http://127.0.0.1:5173>을 엽니다. 화면의 `/api` 요청은 기본 포트 4174의 API 서버로 전달됩니다.

빌드한 화면을 실행하려면 다음 명령을 순서대로 실행합니다.

```bash
npm run build
npm start
```

`npm run build`는 화면을 `dist/`에 생성하고, `npm start`는 빌드 결과와 API를 <http://127.0.0.1:4174>에서 제공합니다. 서버 포트는 `PORT` 환경 변수로 바꿀 수 있습니다. 개발 모드의 API 프록시는 4174로 고정되어 있으므로 기본 포트를 사용하세요.

## 데이터 모드

화면 하단의 **데이터** 선택 메뉴에서 모드를 바꿉니다. 하단에는 기준 시각, 실제 데이터 출처, 수집 범위도 표시됩니다.

| 모드 | 동작 |
| --- | --- |
| 스냅숏 (`snapshot`, 기본값) | `data/snapshot.json`의 저장된 데이터를 사용합니다. GitHub 연결 없이 사용할 수 있으며, 포함된 스냅숏은 2026-10-20 기준 이슈 26개와 릴리스 3개입니다. |
| 실시간 (`live`) | GitHub API에서 이슈·PR 응답 최대 30개와 릴리스 응답 최대 5개를 가져온 뒤 PR, 사전 릴리스, 초안을 제외합니다. 추가 페이지는 조회하지 않습니다. |

실시간 모드의 조회 결과는 서버에서 60초 동안 재사용합니다. 자동으로 주기 갱신되지는 않습니다. GitHub 연결에 실패하면 저장된 스냅숏으로 전환하고 경고를 표시하며, 출처는 `snapshot-fallback`이 됩니다. 이 대체 결과도 60초 동안 재사용됩니다.

## 이슈 검색과 필터

- **제목 또는 번호 검색**: 입력하면 결과가 갱신됩니다. 앞뒤 공백과 맨 앞 `#`을 제거하고 대소문자를 구분하지 않으며, 제목이나 이슈 번호의 일부가 일치하면 표시합니다. 예를 들어 `#12`는 번호에 `12`가 포함된 이슈를 찾습니다.
- **상태**: `모든 상태`, `열림`, `닫힘` 중에서 선택합니다.
- **라벨**: `모든 라벨`, `라벨 없음`, 실제 라벨 이름 중에서 선택합니다.

검색어·상태·라벨 조건은 모두 동시에 적용됩니다. 결과 위의 `전체 N개 중 M개`에서 필터 적용 전후의 개수를 확인할 수 있습니다. **초기화**를 누르면 검색어와 두 필터가 기본값으로 돌아갑니다. 결과가 없을 때는 **조건 초기화** 버튼도 사용할 수 있습니다. 데이터를 불러오지 못하면 오류 메시지의 **다시 시도**를 누르세요.

## 라벨 통계와 릴리스

**라벨별 이슈**는 검색·필터와 무관하게 현재 데이터의 전체 이슈를 집계하여 상위 10개 항목을 보여 줍니다. 같은 이슈의 중복 라벨은 한 번만 세며, 라벨이 없는 이슈는 `라벨 없음`으로 집계합니다. 개수가 많은 순으로 정렬하고, 개수가 같으면 이름순으로 정렬합니다. 여러 라벨이 있는 이슈는 각 라벨에 포함되므로 라벨별 개수의 합이 전체 이슈 수보다 클 수 있습니다.

**릴리스** 탭에서는 정식 릴리스의 게시일, 이름(없으면 태그), 변경 내용 요약을 볼 수 있습니다. 제목이나 **전체 변경 내용 보기 ↗**를 누르면 GitHub 릴리스 원문이 열립니다. 이슈 검색과 필터는 릴리스 목록에 영향을 주지 않습니다.

## 대시보드 API

`GET /api/dashboard`는 화면에서 사용하는 JSON 데이터를 반환합니다. 개발 모드의 화면 주소 또는 API 서버 주소에서 호출할 수 있습니다.

```bash
curl 'http://127.0.0.1:4174/api/dashboard?source=snapshot&query=%2312&state=open&label=all'
```

| 쿼리 매개변수 | 기본값 | 허용 값 및 동작 |
| --- | --- | --- |
| `source` | `snapshot` | `snapshot`, `live` |
| `query` | 빈 문자열 | 제목 또는 번호 부분 일치 검색. 공백·대소문자·맨 앞 `#` 처리는 화면 검색과 동일합니다. |
| `state` | `all` | `all`, `open`, `closed` |
| `label` | `all` | `all`, 실제 라벨 이름, `__unlabelled__`(라벨 없음). 알 수 없는 라벨은 빈 결과를 반환합니다. |

검색과 필터는 서버에서 AND 조건으로 적용합니다. 응답에는 다음 필드가 포함됩니다.

- `repository`, `capturedAt`, `source`, `scope`, `warning`: 저장소, 기준 시각, 실제 출처(`snapshot` / `live` / `snapshot-fallback`), 수집 범위, 경고 메시지(없으면 `null`).
- `issues`, `total`, `filtered`: 필터 결과 배열, 필터 전 전체 이슈 수, 결과 수.
- `labels`: 전체 데이터의 고유 라벨 이름을 정렬한 배열.
- `labelCounts`: 전체 데이터 기준 `{ name, count }` 배열. 라벨 없음도 포함하며 개수 내림차순, 동률은 이름순입니다.
- `releases`: 릴리스 배열. 이슈 필터의 영향을 받지 않습니다.

결과가 없어도 HTTP 200과 `issues: []`, `filtered: 0`을 반환하며 `total`, `labels`, `labelCounts`는 유지합니다. 잘못된 `source`나 `state`는 HTTP 400과 JSON `{ "error": "..." }`, GET 이외의 메서드는 HTTP 405와 `Allow: GET` 헤더를 반환합니다. 데이터 로딩 자체가 실패하면 HTTP 500과 JSON 오류 메시지를 반환합니다.

자세한 계약은 [contract/API.md](contract/API.md)를 참고하세요.

## 테스트

```bash
npm test
npm run accept
```

`npm test`는 데이터 로딩과 대체 동작, 검색·필터·라벨 집계, HTTP API 등을 검사합니다. `npm run accept`는 실제 서버를 띄워 기본 응답, 필터 교집합, 빈 결과, 오류 응답이 API 계약을 따르는지 검사합니다. 두 명령 모두 별도로 개발 서버를 실행할 필요가 없습니다.
